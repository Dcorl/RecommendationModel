Overview

What this application is, in one screen

A content-based recommendation system over a Netflix catalogue of 8,807 titles. A user picks one of 20 curated titles, rates the 10 closest matches, and sees how relevant the model's suggestions were. It is a single Streamlit process — no database, no API layer, no background worker, no persisted state.

Streamlit 1.52.0 or newer is a hard requirement

media_selection.py passes width="content" to st.container(). The parameter did not exist before 1.48.0, and Streamlit's own validate_width rejected the value "content" until 1.52.0. The selection page is the application's entry point, so anything older fails on first render — before a user can click anything.

    Data

    One CSV, three columns, 8,807 rows

    The catalogue is a committed static snapshot from Kaggle, reduced from the source dataset's twelve columns to three. Nothing in the application writes to it, and nothing checks whether it is stale.

    Measured

    Data structure transformation

    Three text columns are concatenated into one synthetic field, then vectorised into a shared term space. Shapes and sizes are measured against the committed snapshot.

    All three fields share one vocabulary, with no field weighting. Descriptions average 24 words against 2–4 genre words, so descriptions dominate the signal by volume.

    Model

    TF-IDF and cosine similarity, rebuilt every click

    There is no supervised learning here: nothing is fit to labels, there is no train/test split, and no artefact is persisted. The model is a deterministic similarity search over a text index constructed at call time.

    Measured

    The pipeline

    Six stages. Select any stage for its shape, cost and citation.

    From catalogue to ten titles

    Stage 4 allocates a dense 620 MB matrix. Stage 5 reads one of its 8,807 rows. The other 99.99% is computed, allocated and discarded.

    Derived

    Called unconditionally at the top of renderRecommendationsPage, so every rating click runs the whole chain again.

    Why 620 MB

    Memory grows with the square of catalogue size. This is a hard ceiling, not a tuning problem.

    Dense similarity matrix size against catalogue size

    n × n × 8 bytes (float64). At today's 8,807 titles that is exactly 620,505,992 bytes.

    Derived

    Plotted logarithmically, so the 620 MB bar stays visible next to 80 GB — the squaring is in the numbers, not the bar heights. The 8 GB line falls between 20,000 and 50,000 titles: the catalogue can roughly double before it stops fitting a typical machine. The fix is not more RAM. Computing cosine_similarity(X[i], X) for the one row that is actually used needs roughly 70 KB instead of 620 MB.

    Vectoriser parameters

    All TfidfVectorizer defaults apply except stop_words. The defaults are doing more work than they appear to.

    Relevance scoring

    The user's ten ratings become a percentage. It is an honest signal — the user's own judgement — but it is not model accuracy in the machine-learning sense.

    What it is

    Yes = 1.0 · Maybe = 0.5 · No = 0.0, averaged over 10

    A single user's in-session satisfaction

    Range 0–100% in steps of 5 points. The UI wording — "X% relevant" — is accurate.

    Deterministic and reproducible

    Same catalogue, same title, same ten recommendations, always.

    What it is not

    Caveats that belong with any quoted figure

    Not accuracy

    No ground-truth labels, no held-out set, no baseline. The internal variable named accuracy is a misnomer.

    n = 10

    Standard error on a proportion at n=10 is roughly 16 points. "70% relevant" is not meaningfully different from "50%".

    Order effects uncontrolled

    Results are always shown best-first, so later items are systematically weaker.

    Nothing persists

    Responses die with the session. The score cannot be tracked over time or compared across model changes.

    The divisor is hard-coded twice

    The count 10 appears independently as the slice [1:11] in recommendation_model.py:26 and as the divisor in model_analysis.py:30. Changing one without the other silently corrupts the score — returning five recommendations would cap the reported relevance at 50%, with no error.
